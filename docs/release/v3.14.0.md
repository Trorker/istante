# Istante v3.14.0

**Data:** 10 settembre 2026  
**Tipo:** revisione strutturale per produzione

La 3.14.0 riparte dalla 3.13.11 mantenendone grafica e funzioni, ma riorganizza
il modo in cui Istante gestisce CSS, viewport mobile, calendari ICS e cache
offline. È una release di consolidamento: meno eccezioni sovrapposte e una
composizione prevedibile sulle diverse misure di schermo.

## Responsive basato sul viewport reale

Il bootstrap misura `visualViewport.width` e `visualViewport.height` e calcola
`viewport-index = width / height`. Oltre alle variabili CSS, espone una classe di
composizione semantica per telefono verticale/orizzontale, tablet e desktop.
La misura viene aggiornata anche quando il browser mobile modifica il viewport.

### Telefono verticale

- Meteo, Prossimo capitolo e Agenda si dispongono **in colonna**.
- L'ordine resta sempre Meteo → Traguardo → Agenda.
- Diminuisce lo spazio tra la frase e la fascia informativa.
- Prima di ridurre i contenuti principali vengono eliminati metadati secondari,
  separatori e spazi non necessari.
- Anche il riepilogo della modalità inattiva segue la stessa composizione.

### Telefono orizzontale

- La fascia informativa passa a circa 38 px di altezza.
- Meteo, traguardo e prossimo evento mantengono il layout su una riga, ma con
  gerarchia e spazi più compatti.
- La toolbar inferiore si ridimensiona in base all'altezza reale del viewport.
- Ora e frase restano visivamente dominanti.

## CSS di produzione

La 3.13.11 caricava più di trenta fogli CSS in cascata, inclusa una lunga serie
`polish-*`. La 3.14.0 consolida la cascata validata senza modificarne l'ordine:

- `assets/css/istante.css`: stile completo della dashboard e delle funzioni;
- `assets/css/responsive.css`: unico livello finale per composizioni viewport;
- `assets/css/documents.css`: stile autonomo della documentazione.

I vecchi file `polish-*` non vengono più pubblicati né richiesti a runtime.
Questo riduce drasticamente le richieste CSS e impedisce che nuove correzioni
responsive vengano distribuite in decine di override successivi.

## API ICS

Aggiunto `api/calendar.php`, un relay PHP provider-agnostic per feed ICS remoti.
Serve a superare i limiti CORS del browser e supporta i normali link HTTPS di
Google Calendar, Outlook / Microsoft 365, iCloud e altri provider ICS.

Il relay:

- usa soltanto POST JSON, così il link privato non entra nella query string;
- non salva feed o URL su file/database;
- accetta soltanto HTTPS sulla porta 443;
- limita il feed a 1 MiB e i redirect a 4;
- rifiuta IP privati, loopback e reti riservate;
- fissa cURL all'IP pubblico appena validato per ridurre il rischio DNS rebinding;
- non espone CORS verso altri siti.

Requisiti hosting: PHP 8.1+ con estensione cURL.

## Offline e service worker

Corretto il manifest della cache offline: la 3.13.11 referenziava ancora
`calendario.html`, file non più presente perché il Calendario è una vista
virtuale di `index.html`. La precache viene ora generata soltanto da file reali
della release. `api/calendar.php` è escluso dalla cache e resta sempre una
richiesta di rete.

## Compatibilità

Preferenze, calendari salvati, raccolte, stazioni e backup mantengono le chiavi
locali già usate dalla 3.13.11. L'aggiornamento non richiede migrazioni dei dati.
