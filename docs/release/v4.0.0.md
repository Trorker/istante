# Istante v4.0.0 — Vue architecture

Data: 10 settembre 2026

## Perché una major release

La v4 riscrive la struttura dell'interfaccia. La grafica e le funzioni maturate
nelle release 3.x restano il riferimento, ma `index.html` non contiene più tutta
l'applicazione e non è più il punto in cui si accumulano correzioni responsive.

## Nuova UI Vue

Tutta la dashboard, il calendario, la toolbar e le modali sono componenti Vue 3.
Il runtime Vue è incluso localmente; non serve una CDN e non serve una build npm
per pubblicare la release.

Sono stati creati componenti dedicati per topbar, scena principale, dock
informativo, toolbar, calendario e ogni dialogo applicativo. La pagina di lettura
dei documenti usa anch'essa un componente Vue.

## Responsive

Il modello responsive è reattivo e distingue Phone, Tablet, Computer e Display.
Il rapporto `vw/vh` determina la composizione; un indice di dimensione del
viewport determina la scala di font e controlli.

Restano valide le correzioni richieste prima della migrazione: timer non
fullscreen su laptop, calendario mobile con gerarchia più pulita, anno non
tagliato e toolbar inferiore stabile sui telefoni.

## Calendario API separabile

`config/runtime.js` permette di impostare un endpoint ICS assoluto. Il frontend
può quindi stare su GitHub Pages mentre `calendar.php` resta sul proprio hosting.
La configurazione di default continua a usare `api/calendar.php` sullo stesso
origin.

## Compatibilità dei servizi

I motori esistenti (radio, timer, ICS, meteo, backup, scene e gesture) vengono
caricati dopo il mount Vue. In questo modo la migrazione strutturale non butta via
logiche già stabili e può essere testata senza introdurre una riscrittura
simultanea di ogni algoritmo.
