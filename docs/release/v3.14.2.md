# Istante 3.14.2

**Data:** 12 settembre 2026  
**Tipo:** aggiornamenti automatici e recupero anti-blocco

## Obiettivo

Questa release rende il passaggio a una nuova versione molto più aggressivo e resistente ai problemi di cache o di pubblicazione. Un singolo asset temporaneamente non disponibile o con hash diverso non può più lasciare Istante bloccato indefinitamente sulla release precedente.

## Modifiche

- **Attivazione automatica:** le release compatibili vengono installate e attivate automaticamente appena il nuovo service worker è pronto.
- **Aggiornamento sempre forzabile:** il comando **Aggiorna ora / Aggiorna comunque** non viene più disabilitato perché manca un file nella cache della nuova release.
- **Verifica non bloccante:** SHA-256 resta un controllo utile per capire se un asset coincide con la build pubblicata, ma un file non verificato non impedisce più l'attivazione.
- **Recupero progressivo:** gli asset mancanti o non verificati vengono richiesti nuovamente anche dopo l'attivazione, fino a convergere sulla build pubblicata.
- **Fallback alla release precedente:** viene mantenuta una cache precedente come rete di sicurezza. Se un asset della nuova release non è ancora disponibile, Istante può usarne temporaneamente la copia precedente invece di restituire una pagina rotta.
- **Badge sul logo:** quando viene rilevata una nuova release compare sul logo un badge diagonale **“Aggiorna alla nuova versione”**, cliccabile per forzare il passaggio.
- **Controlli più frequenti:** Istante ricontrolla la versione quando torna online, quando la pagina torna visibile e periodicamente durante l'uso.

## Compatibilità

Lo schema dati resta alla versione 1. Le preferenze e i backup delle release 3.14.x restano compatibili. In una futura release che richieda uno schema minimo superiore, l'utente viene avvisato ma conserva la possibilità di procedere con **Aggiorna comunque**.

## Nota di pubblicazione

Per la massima affidabilità va comunque caricato l'intero contenuto della release, inclusi `sw.js` e `version.json`. Da questa versione, però, un caricamento non perfettamente atomico non deve più lasciare i client bloccati senza possibilità di aggiornamento.
